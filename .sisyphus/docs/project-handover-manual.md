# ブログ記事プロジェクト 引き継ぎ書 & 運用マニュアル

## 1. プロジェクト概要
- **目的**: 424記事（既存104 + 新規320）のプロ品質化
  - 既存記事のリライトと新規記事の追加により、サイトのコンテンツ密度と専門性を高める。
- **対象ファイル**: `content/blog/*.md`
- **品質基準**: 
  - 図・画像が適切に配置されている
  - AIっぽくない自然な日本語文章
  - 読者が即座に実行できる「実践アクション」が含まれている

## 2. 記事構成要件

### Frontmatter必須項目
すべての記事は以下の形式でFrontmatterを記述する必要があります。
```yaml
---
title: "記事タイトル"
description: "SEO用の概要文（100文字程度）"
date: "YYYY-MM-DD"
category: "カテゴリ名（日本語）"
tags: ["タグ1", "タグ2", "タグ3"]
published: true
slug: "url-slug-kebab-case"
---
```

### 本文構成
1. **はじめに(導入)**: 読者の共感を得る問題提起や問いかけ（2〜3段落）
2. **メインセクション**: 3-4つのセクション（H2見出し）
   - 各セクションに図表（Mermaid）や具体例を交える
3. **実践アクション**: 読者が今日からできる具体的なステップ
4. **まとめ**: 記事の要点を振り返り

### 必須要素
- **Mermaid図表**: 概念の視覚化（1記事1〜3個）
- **文字数**: 800-1500文字を基準とする（標準2000文字以上も可）
- **区切り線**: H2セクション間は `---` で区切る

## 3. カテゴリ体系
原則として以下のカテゴリを使用し、一貫性を保ちます。

- **AI活用**: AIツール活用、プロンプト設計、業務自動化
- **生産性**: 時間管理、タスク管理、集中力向上
- **マインドセット**: 思考法、心理的要因、成長志向
- **コーチング**: 1on1、コミュニケーション、フィードバック
- **キャリア**: キャリア設計、転職、スキルアップ
- **思考法**: ロジカルシンキング、クリティカルシンキング
- **メンタルモデル**: フレームワーク、意思決定

## 4. 品質チェックリスト
公開前に以下の項目を必ず確認してください。
- [ ] タイトルは具体的で、読者の検索意図に応えているか
- [ ] 導入文で読者の「自分事化」ができているか
- [ ] 図表（Mermaid）が本文の理解を助ける位置に配置されているか
- [ ] アクションステップが具体的で実行可能か
- [ ] 誤字脱字、不自然な敬語、AI特有の言い回しがないか
- [ ] タグが適切に3-5個設定されているか

## 5. 図表作成ガイドライン
### Mermaid記法の使用
複雑なプロセスや構造はMermaidで記述します。
- **フローチャート (`graph TD/LR`)**: 手順や因果関係
- **マインドマップ**: 概念の広がり
- **サイクル図**: 習慣やループ構造

### スタイル指針
- 図には必ず前後で説明文を付ける
- プロフェッショナルな配色（青、緑、黄、赤）を意識したキーワード設計
- 複雑すぎる図は避け、1つの図で1つのメッセージを伝える

## 8. トラブルシューティング
- **YAMLパースエラー**: 
  - タイトルにコロン `:` を含める場合は必ずダブルクォーテーションで囲む。
  - インデントはスペース2つ。
- **重複タイトルの検出**:
  - `grep -r "title:" content/blog/` で重複を確認。
- **ビルドエラー**:
  - `npm run build` を実行し、Markdownのレンダリングエラーがないか確認。
- **Git管理**:
  - 1記事1コミットを推奨。コミットメッセージは `feat(blog): add article 161 [slug]` 形式。

## 9. ファイル命名規則
- **フォーマット**: `XXX-[kebab-case-slug].md`
  - `XXX`: 3桁の連番（001, 013, 161など）
  - `kebab-case-slug`: 英語の小文字とハイフンのみ。
- **既存**: `013-116`（既存記事の管理番号を維持）
- **新規**: `001-320`（新規シリーズとしての連番）
