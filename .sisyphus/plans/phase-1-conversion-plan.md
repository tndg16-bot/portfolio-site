## 📝 作業フロー

### Step 1: 分析フェーズ（約40分）

#### 1.1 テンプレートの読み込み

```bash
# テンプレート1-320件をリスト化
ls content/blog/ | grep "\.md$" | grep -E "^[0-9]{4,}" | head -320 > phase1-templates.txt
```

#### 1.2 カテゴリ・タグの確認

- 各テンプレートのfrontmatterを解析
- カテゴリの一覧を作成
- タグの一覧を作成

#### 1.3 既存記事との重複確認

- テンプレートと既存記事のタイトルを比較
- 重複があれば統合計画を策定

### Step 2: 変換フェーズ（約120分）

#### 2.1 テンプレートを実際の記事に変換

**変換のポイント**:
- タイトル: テンプレートのタイトルを活用
- カテゴリ: テンプレートのカテゴリを活用
- タグ: テンプレートのタグを活用
- 内容: テンプレートの内容を充実化

**変換方法**:
1. テンプレートのfrontmatterを確認
2. テンプレートの内容を分析
3. 実際の記事の内容を生成
4. frontmatterを更新
5. 記事を保存

#### 2.2 ファイル名の変更

```bash
# テンプレートファイル名を実際の記事ファイル名に変更
# 例: 0101--.md → 117-coaching-principles.md
```

### Step 3: レビューフェーズ（約20分）

#### 3.1 記事の品質確認

- タイトルが適切か
- カテゴリが正しいか
- タグが適切か
- 内容が充実しているか

#### 3.2 SEOチェック

- メタディスクリプションが設定されているか
- slugが適切に設定されているか
- 内部リンクが設定されているか

### Step 4: 完了フェーズ（約20分）

#### 4.1 ファイルの保存

- 変換した記事を保存
- ファイル名を更新

#### 4.2 Git commit

```bash
# 変更を反映
git add content/blog/
git commit -m "Phase 1: Convert 320 templates to articles"
```

#### 4.3 進捗報告

- フェーズ1の完了報告を作成
- 変換した記事の一覧を作成
- 次のフェーズへの移行準備

## 🚨 注意点

### 変換時の注意点

1. **タイトルの重複回避**
   - 既存記事と同じタイトルにならないように注意
   - 必要に応じてタイトルを調整

2. **カテゴリのバランス**
   - 7カテゴリにバランスよく配分
   - 偏りを回避

3. **タグの適切な設定**
   - 各記事に適切なタグを設定
   - タグの過度な使用を回避

### 質の回避

1. **内容の重複**
   - 既存記事と同じ内容にならないように注意
   - 必要に応じて統合

2. **品質の維持**
   - すべての記事が高品質であることを確認
   - 粗雑な変換を回避
