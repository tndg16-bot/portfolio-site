# GitHub Projects タスク管理チュートリアル

**作成日**: 2026-01-16
**目的**: GitHub Projectsでのタスク管理改善と整理

---

## 現状の問題点

### 1. GitHub API認証エラー
- **エラー**: `The token in GITHUB_TOKEN is invalid`
- **影響**: Issueへのコメント追加、Pull Requestの作成が不可
- **原因**: 環境変数に古いトークンが残っている

### 2. GitHub Projects の利用制限
- **問題**: GitHub Projects がAPI認証問題により制限されている
- **影響**: タスクの進捗が可視化できない
- **現状**: ローカルでのタスク管理に切り替え

### 3. タスク管理の複雑化
- **問題**: 3つのBusiness Issues（#83, #84, #85）が個別に管理
- **影響**: 全体像が見えにくい
- **現状**: 統合的なタスク管理ドキュメントで代替

---

## 代替策の検討

### オプションA: ローカルタスク管理（現在のアプローチ）
| メリット | デメリット |
|----------|------------|
| GitHub APIに依存しない | 進捗が可視化されにくい |
| 自由度が高い | Issueへのコメント不可 |
| 迅速に開始できる | GitHub上での追跡が困難 |

### オプションB: GitHub API認証の解決
| メリット | デメリット |
|----------|------------|
| Issueへのコメントが可能 | 新しいトークンの作成が必要 |
| Pull Requestの作成が可能 | トークンの管理が面倒 |
| 進捗を可視化できる | 作業のオーバーヘッドあり |

---

## 推奨されるアクション

### アクション1: GitHub API認証の解決（推奨）
1. **新しいPersonal Access Tokenを作成**
   - https://github.com/settings/tokens にアクセス
   - "Generate new token (classic)" をクリック
   - Note: `portfolio-development`
   - Expiration: 90日推奨
   - Scopes: `repo` にチェック

2. **環境変数の更新**
   - ローカルで `.env.local` を更新
   - 古い `GITHUB_TOKEN` を削除

3. **認証の確認**
   ```bash
   gh auth status
   ```

4. **Issueへのコメント追加**
   ```bash
   gh issue comment 83 --body "## 並列開発計画の作成完了"
   ```

### アクション2: ローカルでのタスク管理（現在実行中）
1. 作成されたタスク一覧を確認
   - `docs/plans/LOCAL_DEVELOPMENT_TASKS.md`
   - `docs/plans/DEVELOPMENT_TASKS.md`

2. 優先度の高いタスクから開始
   - ブログ読みやすさ改善: ✅ 完了
   - プロジェクト管理機能の改善
   - コンテンツの充実

3. 進捗の記録
   - 各タスクの完了時にチェックボックスを更新
   - 毎週のステータス確認

## タスク管理のベストプラクティス

### 1. タスクの粒度
- **大粒度**: プロジェクト全体（例: ビジネス開発）
- **中粒度**: 機能やフェーズ（例: プロジェクト管理機能実装）
- **小粒度**: 具体的なアクション（例: タスク管理ツールの調査）

### 2. 進捗の定義
- [ ] 未着手
- [ ] 進行中
- [ ] レビュー待ち
- [x] 完了

### 3. 依存関係の明確化
- タスクAが完了してからタスクBに開始
- ブロックされるタスクを明確にする
- 循環依存を避ける

### 4. 期限の設定
- 各タスクに適切な期限を設定
- 緊急のタスクには短い期限を
- 時間に余裕を持たせる

### 5. 定期的な見直し
- 週に1回、進捗を確認
- 優先度の調整
- リスクの評価
