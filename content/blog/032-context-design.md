## はじめに

「プロンプトエンジニアリング」という言葉が広まっていますが、AIから真に良い成果を引き出すには、単なる「指示」の技術を超えた「コンテキスト設計」が必要です。背景情報、文脈、制約条件をどう伝えるかが、AIの出力の質を決定します。この「コンテキスト設計」の極意を解説します。

## プロンプトとコンテキストの違い

### プロンプトの限界

プロンプトは「指示」ですが、それだけでは不十分なことがあります。

**例：単純なプロンプト**
```
「マーケティング戦略を立ててください」
```

**問題点：**
- 業界が不明
- ターゲットが不明
- 目的が不明
- 制約が不明

→ 一般的で実用性の低い回答になりがち

### コンテキスト設計の力

コンテキストは「状況」を含めた設計です。

**例：コンテキストを含めた設計**
```
【背景】
- 業界：BtoB SaaS
- 製品：プロジェクト管理ツール
- フェーズ：成長期から成熟期へ

【ターゲット】
- 中小企業のIT部門責任者
- 現在の課題：ツールの使いこなし不足

【目的】
- 既存顧客の継続率向上（現在85%→目標90%）
- アップセル率の向上

【制約】
- 予算：100万円
- 期間：3ヶ月
- リソース：マーケ担当2名

【依頼】
この状況に最適なマーケティング戦略を3案提案してください。
```

→ 文脈を理解した上で、実用的な提案が得られます

## コンテキスト設計の4要素

### 要素1：Who（誰が、誰に）

**自分のプロファイル：**
- 専門性や立場
- 知識レベル
- 利用目的

**相手/ターゲットのプロファイル：**
- 読み手/利用者は誰か
- 彼らの知識レベル
- 期待する価値

**例：**
```
「私は○○業界で5年目の営業です。
専門知識は中級レベルです。
この資料は、技術的な知識が少ない経営層向けです。」
```

### 要素2：What（何を、何のために）

**目的とゴール：**
- 最終的に得たい成果
- この出力の用途
- 成功の定義

**具体性のレベル：**
- 概念レベル（アイデア出し）
- ドラフトレベル（推敲が必要）
- 完成レベル（そのまま使える）

**例：**
```
「この文章は、週次の進捗報告メールとして使用します。
上司が現状を素早く把握でき、次のアクションを判断できることを目指します。
修正なしで送信できるレベルでお願いします。」
```

### 要素3：When/Where（いつ、どこで）

**時間的文脈：**
- 締め切り
- 時期的背景
- タイムライン

**場所的文脈：**
- 地域や文化
- 組織や業界
- プラットフォーム

**例：**
```
「これは来週の四半期レビュー会議（3月15日）で使用します。
日本の製造業向けのプレゼン資料です。
会議時間は30分で、参加者は部門長5名です。」
```

### 要素4：How（どのように）

**トーンとスタイル：**
- フォーマル/カジュアル
- 簡潔/詳細
- 論理的/感情的

**出力形式：**
- フォーマットの指定
- 長さの制約
- 構造の指定

**例：**
```
「トーンはビジネスフォーマルで、簡潔にお願いします。
出力は以下の形式で：
1. エグゼクティブサマリー（3行）
2. 詳細（箇条書き）
3. 推奨アクション（3つ）
全体で1ページ以内にしてください。」
```

## コンテキスト設計の実践テクレニック

### テクニック1：階層的なコンテキスト提供

全てを一度に伝えるのではなく、段階的に深めます。

**レベル1：基本文脈**
```
「○○業界で△△という課題を解決する企画書を作成しています。」
```

**レベル2：詳細情報**
```
「ターゲットは□□で、現在の市場規模は◇◇です。
競合は■■と□□□で、私たちの差別化ポイントは◆◆です。」
```

**レベル3：具体的な依頼**
```
「エグゼクティブサマリーを作成してください。
トーンは説得力があり、かつ簡潔に。」
```

### テクニック2：制約条件の明示

「何を避けるべきか」も伝えます。

**例：**
```
「以下の条件で作成してください：
- 含めるべき内容：A、B、C
- 避けるべき内容：X、Y、Z
- 長さ：500字以内
- トーン：感謝を示しつつ、明確に断る」
```

### テクニック3：サンプルによる学習

望ましい出力の例を示します。

**例：**
```
「以下のようなトーンと構成で作成してください：

【参考例】
（理想的な出力の例を提示）

【今回の依頼】
上記のスタイルで、以下の内容について...」
```

### テクニック4：反復的な改善

1回で完璧を目指さず、対話で深めます。

**改善のサイクル：**
```
1回目：基本的なコンテキストで依頼
→ フィードバック：「もっと詳細に」「もっと簡潔に」等

2回目：フィードバックを反映
→ さらに微調整の指示

3回目：ほぼ完成に近づく
→ 最終調整
```

## よくあるコンテキストミス

### ミス1：文脈の不足

**悪い例：**
```
「良いアイデアをください」
```

**改善：**
```
「私は○○業界の新規事業担当で、△△という課題を解決したいと考えています。
ターゲットは□□で、予算は◆◆です。
技術的には◇◇が可能です。
この状況で実現可能なアイデアを3つ提案してください。」
```

### ミス2：矛盾した指示

**悪い例：**
```
「詳しく説明してください。200字以内で。」
```

**改善：**
```
「核心をシンプルに説明してください。200字以内で。
詳細は別途提供します。」
```

### ミス3：過度な前提

**悪い例：**
```
「この業界の常識として...」（AIが知らないかもしれない）
```

**改善：**
```
「○○業界では、通常△△という前提で進めます。
この前提で検討してください。」
```

## コンテキスト設計のテンプレート集

### テンプレート1：戦略立案

```
【背景】
- 業界/市場：
- 自社のポジション：
- フェーズ：

【課題】
- 現在の状況：
- 解決すべき問題：
- 機会：

【制約】
- 予算：
- 期間：
- リソース：
- その他の制限：

【目標】
- 具体的なKPI：
- 成功の定義：

【依頼】
```

### テンプレート2：文章作成

```
【読み手】
- 誰：
- 知識レベル：
- 期待する価値：

【目的】
- この文章で達成したいこと：
- 読み手にどうなってほしいか：

【トーン】
- スタイル：
- 避けるべき表現：

【形式】
- 長さ：
- 構成：
- 特殊な要件：

【依頼】
```

## まとめ：文脈を設計し、AIを味方にする

コンテキスト設計は、AIとの協働における最も重要なスキルです。正しい文脈を提供することで、AIは単なるツールから、真のパートナーへと変わります。

**今週から始めるステップ：**
1. 今週：過去の失敗したプロンプトを3つ振り返り、文脈不足を特定
2. テンプレートを3つ作成し、活用開始
3. 効果的だったコンテキスト設計を記録し、再利用
4. チーム内でコンテキスト設計のベストプラクティスを共有

文脈を設計し、AIの可能性を最大限に引き出しましょう。
