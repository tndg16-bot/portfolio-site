## はじめに

「いろいろな事例を見てきたけど、
なかなかパターンが見えない...」

「経験はあるのに、
それを言語化して伝えるのが難しい...」

そんな悩み、ありませんか？

経験を「知恵」に変えるのが、
**「概念化」の力**です。

個別の出来事から、
普遍的な法則を引き出す。

このスキルが、
リーダーとフォロワーを分けます。

---

## 概念化とは何か

### 具体と抽象の階段

```mermaid
graph TD
    A[具体的事例<br/>山田さんが残業で倒れた] --> B[類似事例<br/>他にも体調不良者が出ている]
    B --> C[パターン<br/>長時間労働が健康に影響]
    C --> D[概念<br/>働き方改革の必要性]
    D --> E[普遍的法則<br/>持続可能な働き方が<br/>生産性を高める]
```

**具体的事例 → 概念 → 普遍的法則**

この階段を上る力が、
概念化スキルです。

### なぜ概念化が重要か

```mermaid
graph TD
    A[概念化なし]
    A --> B[事例の羅列]
    B --> C[経験に依存]
    B --> D[応用が効かない]
    
    E[概念化あり]
    E --> F[パターンの理解]
    F --> G[新しい状況にも適用]
    F --> H[他者への説明が容易]
```

## 概念化の実践ステップ

### ステップ1：事例を集める

```mermaid
graph LR
    A[事例1] --> D[共通点を探す]
    B[事例2] --> D
    C[事例3] --> D
    D --> E[パターン発見]
```

同じような状況が3つ以上あったら、
**偶然ではなく「パターン」**です。

### ステップ2：「つまり」を探す

```mermaid
graph TD
    A[事例を並べる] --> B[共通要素は？]
    B --> C[何が起きている？]
    C --> D[一言で言うと？]
    D --> E[概念の誕生]
```

**「つまり、これは〇〇ということだ」**

この一言が概念です。

### ステップ3：名前をつける

```mermaid
graph TD
    A[概念を見つける] --> B[適切な名前をつける]
    B --> C[定義を明確にする]
    C --> D[他の人にも<br/>説明できる]
```

名前があると、
**議論の共通言語**になります。

## 概念化スキルのトレーニング

### 日常の練習

```mermaid
graph LR
    A[今日の出来事] --> B[何かパターンは？]
    B --> C[つまり...]
    C --> D[一言で表現]
```

毎日1つ、
経験を概念化してみましょう。

### 読書での練習

```mermaid
graph TD
    A[本を読む] --> B[具体例を見つける]
    B --> C[筆者の言いたいことは？]
    C --> D[自分の言葉で<br/>概念化してみる]
    D --> E[筆者の概念と<br/>比較する]
```

### 会議での練習

```mermaid
graph TD
    A[議論が散らばる] --> B[「つまり」でまとめる]
    B --> C[「今の議論は<br/>〇〇ということですね」]
    C --> D[全員の認識を合わせる]
```

## 実践できること

**① 「つまりノート」をつける**

毎日の経験から、
「つまり、これは〇〇だ」
を1つ書き出す。

**② 本の「概念」を抜き出す**

読んだ本から、
著者の核心的な概念を
3つ抜き出してみる。

**③ 会議で「まとめ役」を担う**

議論が散らばった時、
「つまり、今の話は...」
と概念化してみる。

**④ 自分の仕事に「名前」をつける**

自分がやっている独自の方法に、
オリジナルの名前をつけてみる。

## まとめ

概念化とは、
**「見えているのに見えないもの」を
見える形にする**力です。

個別の経験を、
普遍的法則に昇華する。

その力が、
**リーダーの判断力**となり、
**組織の共通言語**となり、
**新しい価値**を生み出します。

経験をため込むのではなく、
経験を概念化して、
知恵に変えていく。

それが、
成長の加速器となります。
